    Azure Cloud Shell + VS Code for the Web (추천)¶

    로컬 설치 없이 실습하기

    Azure Cloud Shell에는 Azure CLI, Terraform, kubectl, git이 모두 사전 설치되어 있습니다. Cloud Shell에서 "Open in VS Code for the Web" 버튼을 누르면 브라우저에서 VS Code 환경을 바로 사용할 수 있습니다. 로컬에 아무것도 설치하지 않고 모든 Lab을 진행할 수 있습니다.

    시작 절차¶

    1. Cloud Shell 열기¶

    아래 두 가지 방법 중 하나를 사용합니다.

    • Azure Portal: https://portal.azure.com 상단 메뉴바의 Cloud Shell 아이콘 (>_) 클릭
    • 직접 접속: https://shell.azure.com

    처음 사용 시 Bash를 선택합니다.

    최초 실행: 스토리지 없이 시작 (권장)¶

    Cloud Shell을 처음 열면 스토리지(Storage account) 연결 화면이 나옵니다. 강의 실습에서는 아래를 권장합니다.

    1. 고급 설정 또는 Show advanced settings 를 펼칩니다(화면에 따라 이름이 다를 수 있음).
    2. 스토리지 없이 계속 / No storage account required / Continue without storage account 와 같이 저장소를 만들지 않는 옵션을 선택합니다.
    3. Create 또는 시작 으로 Cloud Shell을 연다.

    왜 스토리지 없이?

    • 추가 리소스(Storage account, Azure Files)를 만들지 않아 설정이 단순하고, Cloud Shell 전용 스토리지 비용이 0에 가깝습니다.
    • 수업 중에는 git clone으로 Lab 코드를 받고, 세션이 끊기면 다시 clone하면 됩니다. Terraform state는 Azure(RG) 쪽에 있으므로, 세션만 새로 열면 terraform plan으로 이어서 확인할 수 있는 경우가 많습니다.

    스토리지 없이 선택했을 때의 한계

    • 컨테이너의 $HOME 아래에 만든 파일(예: clone한 폴더, ~/bin에 둔 바이너리)은 세션이 종료되면 사라질 수 있습니다. (약 20분 무활동 등)
    • 여러 날에 걸쳐 같은 로컬 작업 디렉터리를 유지하고 싶다면, 나중에 Cloud Shell 설정(톱니바퀴) → 스토리지 연결에서 Storage를 붙이거나, 처음부터 Mount storage account 를 선택해도 됩니다.

    이미 스토리지를 연결한 경우

    처음에 Storage를 만들었다면 그대로 사용해도 됩니다. 스토리지 없이만 쓰고 싶다면 Cloud Shell 상단 설정(톱니바퀴) → Reset user settings 로 초기화한 뒤, 다시 연 때 No storage account required 를 고르면 됩니다. (기존 Storage 리소스는 구독에 남아 있을 수 있으니, 비용이 걱정되면 Portal에서 해당 Storage를 삭제하세요.)

    (참고) 스토리지를 마운트하는 경우¶

    • Mount storage account — Azure Files 마운트. ~/clouddrive/ 등에 파일이 세션 간 유지됩니다. 소량의 스토리지 요금이 발생할 수 있습니다.
    • 장기 보관·로컬 파일 유지가 필요할 때만 선택해도 늦지 않습니다.

    2. VS Code for the Web 열기¶

    Cloud Shell 터미널 상단 툴바에서 "Open in VS Code for the Web" 버튼을 클릭합니다.

    새 브라우저 탭에 VS Code 웹 환경이 열리며:

    • 왼쪽: 파일 탐색기 (Cloud Shell 파일 시스템)
    • 아래쪽: 통합 터미널 (Cloud Shell과 동일한 Bash 세션)
    • 가운데: 에디터 (.tf, .yaml 등 편집)

    인증과 Terraform

    Cloud Shell·VS Code for the Web은 Portal 로그인과 연동되어 이미 CLI에 세션이 있을 수 있습니다.
    그래도 실습에서는 az login --use-device-code로 한 번 명시적으로 로그인한 뒤 Terraform을 실행하는 것을 권장합니다. (브라우저 팝업이 막힌 환경, 토큰 만료, 구독 선택 오류를 줄이기 위함입니다.)

    Terraform(AzureRM provider)은 별도 terraform login 없이, 위 CLI 로그인으로 받은 사용자 자격 증명을 그대로 사용합니다.

    Azure CLI 로그인 — az login --use-device-code¶

    VS Code for the Web 터미널에서 다음을 실행합니다.

    az login --use-device-code
    1. 터미널에 표시되는 코드를 복사합니다.
    2. 브라우저에서 안내된 Microsoft 디바이스 로그인 페이지를 열고, 코드를 붙여넣은 뒤 본인 Entra 계정으로 로그인합니다.
    3. 완료되면 터미널로 돌아와 Login succeeded 등 메시지가 나오는지 확인합니다.

    구독이 여러 개이면 강사가 알려준 구독으로 맞춥니다.

    az account list -o table
az account set --subscription "<SUBSCRIPTION_ID>"
az account show -o table

    이후 terraform plan / apply는 이 CLI 컨텍스트를 사용합니다. 토큰 오류가 나면 같은 방식으로 다시 az login --use-device-code 하면 됩니다.

    참고: Azure CLI로 로그인 (디바이스 코드 흐름)

    Graph 스코프 오류 등

    terraform plan 시 Graph 관련 오류가 나면 Azure 접근 및 Terraform 인증의 az login --scope … 안내를 참고하세요. Cloud Shell에서도 동일하게 적용됩니다.

    3. 도구 및 Azure 환경 확인¶

    위 az login --use-device-code 및 필요 시 az account set까지 마친 뒤, VS Code for the Web 터미널에서 아래를 실행해 도구와 구독·RG 컨텍스트를 확인합니다.

    # Azure CLI
az version --output yaml

# 현재 선택된 구독 (강사가 알려준 구독과 이름·ID가 맞는지)
az account show -o table

# 본인 Resource Group이 목록에 보이는지 (이름은 강사 안내와 일치)
az group list --query "[?starts_with(name,'rg-az104')].{Name:name,Location:location}" -o table

# Terraform / kubectl / Git
terraform version
kubectl version --client
git --version
    확인 항목 기대
    az account show 강사가 안내한 subscription이 선택되어 있음
    az group list 본인 rg-az104-studentXX 가 보임
    terraform version 실습 권장 v1.6.0 이상 (아래 참고)
    kubectl version --client 클라이언트 버전 출력
    git --version 버전 출력

    Terraform 버전이 낮을 때

    Cloud Shell 기본 Terraform이 v1.6.0 미만이면, 아래처럼 사용자 디렉터리에 올려 PATH를 앞에 두고 다시 terraform version으로 확인합니다. (스토리지 없이 쓰는 경우 세션이 끊기면 ~/bin이 사라질 수 있어, 필요할 때마다 실행하면 됩니다.)

    mkdir -p ~/bin
curl -fsSL https://releases.hashicorp.com/terraform/1.14.0/terraform_1.14.0_linux_amd64.zip -o /tmp/tf.zip
unzip -o /tmp/tf.zip -d ~/bin
export PATH="$HOME/bin:$PATH"
terraform version

    비용¶

    항목 비용
    Cloud Shell 컴퓨팅 무료 (Azure 제공 임시 머신)
    VS Code for the Web 무료 (Cloud Shell 연동, 추가 리소스 없음)
    스토리지 (Mount 선택 시) Azure Files 요금 — 스토리지 없이 시작하면 이 항목 없음
    Lab 리소스 Terraform으로 생성하는 Azure 리소스(VM, AKS 등) 비용은 로컬이든 Cloud Shell이든 동일

    출처: Azure Cloud Shell Pricing

    "Cloud Shell is a free service. You only pay for the underlying Azure resources that are consumed."

    주의 사항¶

    항목 설명
    세션 타임아웃 20분 무활동 시 세션 종료. 터미널에서 주기적으로 작업하면 유지됨
    동시 사용자 테넌트당 20명 제한. 초과 시 "Tenant User Over Quota" 에러
    파일 유지 스토리지 없음: $HOME·clone 폴더는 세션 종료 후 사라질 수 있음 → 필요 시 재 git clone. Mount: terraform.tfvars 등 로컬 파일 유지 가능
    붙여넣기 브라우저에서 Ctrl+V (Windows) / Cmd+V (macOS) 정상 동작

    세션이 끊겼을 때

    다시 shell.azure.com 접속 → VS Code for the Web 재실행하면 됩니다. 스토리지를 마운트한 경우에만 ~/clouddrive/ 아래 파일이 세션 간 유지됩니다. 스토리지 없이 쓰는 경우에는 Lab 폴더를 다시 git clone 하면 됩니다.

    로컬 환경과 비교¶

    로컬 (Windows/macOS) Cloud Shell + VS Code Web
    설치 필요 Azure CLI, Terraform, kubectl, Git 없음
    에디터 VS Code Desktop, 기타 VS Code for the Web (브라우저)
    인증 az login (브라우저 리다이렉트) 자동 (Portal 로그인 상태 사용)
    네트워크 회사 방화벽 영향 가능 Azure 내부에서 직접 통신
    파일 유지 로컬 디스크 스토리지 없음: 세션 한정 / Mount 시: Azure Files (clouddrive)

    이후 Lab 진행¶

    환경 확인이 끝나면 실습 저장소를 clone한 뒤(아래 마지막 절), 각 Lab별 절차는 다음을 따릅니다.

    • Terraform Lab 목록 및 시작
    • 커리큘럼 한 페이지

    실습 저장소 받기 (Git clone)¶

    VS Code for the Web 터미널에서 실행합니다.

    cd ~
mkdir -p git && cd git
git clone https://github.com/noisonnoiton/az-104-labs.git
cd az-104-labs
ls

    강사가 다른 URL을 안내한 경우

    위 git clone 주소를 강사가 알려준 저장소 URL로 바꿉니다.

    Private 저장소이면 HTTPS + PAT 또는 SSH 등 강사 안내에 따릅니다. (Git clone 상세 — 경로 B 문서와 동일한 내용)
